22 · The 2026 Frontier

Everything so far is settled engineering. This chapter is the moving edge: what changed in the last two years, what is actually shipping in production today, and which of it is likely to still matter in three years. Most of it is one question asked several ways: how do you stop paying for every past token on every new one? Sparse attention looks at fewer of them, sliding windows forget the old ones, and linear attention compresses all of them into a fixed-size memory. The middle of the chapter builds that last idea, the delta rule, from scratch, because it is now inside two major labs' production models. Read the rest with more scepticism than the rest of the course.

The whole chapter in six sentences

Softmax attention keeps every past key and value, so its memory grows with the context and every new token reads all of it. Sparse and windowed attention read fewer of them; gpt-oss alternates 128-token windows with full layers and gives every head a learned "attend to nothing" sink. Linear attention drops the softmax, which lets the past be summed into one d×d matrix, a fast-weight memory that is written once per token and read by a matrix-vector product. The delta rule writes into that memory by correcting its error rather than adding blindly, which is one step of gradient descent per token, and a forget gate turns it into Gated DeltaNet. Chunking makes it trainable: inside a chunk everything is a matmul, and only the chunk-to-chunk state is sequential. A fixed-size memory cannot recall arbitrary old tokens exactly, so Qwen3-Next and Kimi Linear keep one full-attention layer in four.

22.1 · Sparse attention: not attending to everything

FlashAttention removed the memory wall but left the FLOPs quadratic (Chapter 17). At 128k+ tokens that quadratic finally dominates. The 2025–2026 answer is to make attention genuinely sparse — compute only the scores that matter.

DeepSeek Sparse Attention (DSA)

Shipped in DeepSeek-V3.2. The mechanism has two stages:

  1. Lightning indexer. A very cheap scoring network — few heads, low-rank projections, FP8 arithmetic — scores every previous token against the current query using a ReLU-gated dot product. It is roughly an order of magnitude cheaper per FLOP than the main MLA attention.
  2. Top-k selection, then real attention. Take the k highest-scoring positions and run full MLA attention over only those.
O(L²)  →  O(L·k)     with k ≪ L the indexer still scans all L, but at a small constant; the expensive attention sees only k

DeepSeek reports substantial long-context training and inference speedups at "virtually identical" output quality. The related earlier work, NSA (Native Sparse Attention), trains sparsity in from scratch rather than retrofitting it, combining coarse token compression, selective fine-grained attention, and a sliding window.

Why this took so long

Sparse attention is an old idea (Longformer, BigBird, Reformer, 2020). Those used fixed patterns — strided, local, random — chosen in advance, and they consistently lost to dense attention on quality. The 2025–26 versions are learned and content-dependent: which tokens matter is decided per query at runtime. That difference, plus hardware-aware kernels that make irregular access patterns actually fast, is what finally made sparsity competitive.

22.2 · Windows and sinks: the cheap version (gpt-oss)

The simplest sparsity is a fixed one: let a layer see only the last w tokens. A sliding-window layer's KV cache stops growing at w entries, and its cost per token is O(w) instead of O(T). Used alone it cannot see far, so models alternate window layers with full ones. OpenAI's open-weights gpt-oss models (August 2025) do exactly this. Their model card states that attention blocks "alternate between banded window and fully dense patterns", with a band of 128 tokens, following GPT-3. Gemma 2 alternates windows and global layers 1 : 1, Gemma 3 uses 5 : 1 (Chapter 21).

The memory arithmetic, for gpt-oss-120b (36 layers, 8 KV heads of width 64, bf16 cache):

full layers (18):    18 × 2 (K and V) × 8 heads × 64 × 2 bytes = 36,864 bytes per token
window layers (18):  the same 36,864 bytes × 128 tokens          = 4.7 MB, then it stops growing

at a 131,072-token context:
  alternating:       36,864 × 131,072 + 4.7 MB   = 4.83 GB + 0.005 GB
  all 36 layers full                             = 9.66 GB

So alternation halves the cache at long context, almost exactly: the window layers' contribution is a rounding error. That is the cheap end of the design space. The rest of this chapter is about the expensive end, where most layers keep no per-token cache at all.

Attention sinks: letting a head attend to nothing

A softmax must sum to 1. A head that has nothing useful to read at this position still has to put its weight somewhere, and trained models learn to dump it on the first token, which then acts as an attention sink (Xiao et al. 2023 found this, and that evicting the first token from a sliding-window cache makes such models fall apart). Chapter 5 shows the mechanism in detail. gpt-oss makes the sink explicit: in its model card's words, "each attention head has a learned bias in the denominator of the softmax", so the head can pay "no attention to any tokens". That is one extra logit with no value behind it.

Worked example — one learned sink logit

Three real scores [2.0, 1.0, 0.5] and a sink logit s that joins the softmax but has no value vector (tfs.foundations.softmax_with_sink):

1
No sink (s = −∞, ordinary softmax): weights 0.6285 0.2312 0.1402, sum 1.0000. The head must read something.
2
s = 0 (the fixed "off-by-one" softmax, exi / (1 + Σ exj)): weights 0.5793 0.2131 0.1293, sum 0.9216. 7.8% of the mass goes nowhere.
3
s = 4 (learned, large): the real weights sum to 0.1772. The head is mostly switched off at this position, without having to find a junk token to park its attention on.

Because s is a learned parameter per head, each head decides how readily it abstains. The cost is one scalar per head and one extra term in every softmax denominator; FlashAttention-style kernels fold it into the running sum of Chapter 17's online softmax.

22.3 · Linear attention: a memory you write into

Go back to one head of causal attention (Chapter 5). For the query at position t:

ot = Σi≤t softmaxi(qt·ki) vi every past (ki, vi) pair is kept, and every one is touched again for every new query

The softmax is what forces that. Its normaliser couples query t to all keys at once, so the only way to compute ot is to keep all of them. Delete the softmax (Katharopoulos et al. 2020, "Transformers are RNNs") and use the raw dot product as the weight. Then the sum can be regrouped, because a dot product times a vector is a matrix times a vector:

ot = Σi≤t (qt·ki) vi = ( Σi≤t vi kiᵀ ) qt = St qt St is a dv × dk matrix: the whole past, summed

The bracket does not depend on the query. Call it the state St. It obeys a one-line recurrence, and that recurrence is the whole layer at inference time:

St = St−1 + vt ktᵀ      ot = St qt write: add an outer product (dv·dk FLOPs)  ·  read: one matrix-vector product  ·  memory: dv·dk, forever

Follow the shapes, per head, as tfs/linear_attention.py writes them:

q_t, k_t        (dk,)        this token's query and key
v_t             (dv,)        this token's value
S               (dv, dk)     the state: maps a key to a value
S + outer(v, k) (dv, dk)     write: v k^T has rank 1
S @ q_t         (dv,)        read: what does the memory return for this query?

Why it is called a fast-weight memory

Look at what S is: a matrix that takes a dk-vector and returns a dv-vector. It is a linear layer. The model's ordinary weights (WQ, WK, WV) change slowly, once per optimizer step, and are the same for every input. S is a second set of weights that changes at every token, is different for every sequence, and is thrown away at the end. The slow weights learn what to write (which keys and values to produce); the fast weights hold what was written. Schmidhuber called this a fast-weight programmer in 1992; Schlag, Irie and Schmidhuber (2021) showed linear attention is exactly one.

Writing v kT into S stores an association "key k → value v": if you later read with q = k and k has unit length, S k = v (k·k) = v. Reading with any query returns a mixture of every stored value, weighted by how similar its key is to the query. That is attention's soft lookup (Chapter 5), but stored in a fixed-size matrix instead of a growing list.

The same output can also be computed all at once, like attention, without the recurrence: O = ((Q Kᵀ) ⊙ M) V with M the causal mask and no softmax. test_ch22_linear_attention_two_forms checks that the two forms agree. The parallel form costs O(T²) like attention; the recurrent form costs O(T) but is sequential. Section 22.5 gets the best of both.

What a sum cannot do: forget, or overwrite

Plain linear attention only ever adds. Two consequences follow, and both are fatal at scale.

The second problem is interference. A dk-dimensional key space holds at most dk mutually orthogonal keys. Real keys are not orthogonal, and there are far more tokens than dimensions. Reading key j returns its own value plus (ki·kj) vi from every other stored pair. For random unit keys each dot product is about ±1/√dk, so with n pairs stored the noise grows like √((n − 1)/dk) times the signal. LA.recall_error measures it: store n random pairs in one dk = 64 head, read each key back, report the mean relative error.

At n = dk the noise is already as large as the signal; at 1024 pairs it is four times larger. Softmax attention, which keeps every pair and sharpens onto the best match, reads every one back exactly. With orthogonal keys (n ≤ dk) linear attention is exact too: the problem is not the read, it is that a sum of rank-1 writes has nowhere to put the 65th fact. This table is the reason linear attention lost to softmax attention for five years.

22.4 · The delta rule: write by correcting the error

The fix is to write the difference between what the memory currently returns for a key and what it should return. Before writing (kt, vt), ask the memory what it thinks kt maps to, St−1kt, and write only the correction, scaled by a write strength βt ∈ (0, 1) that the model computes per token (a sigmoid of a projection of xt):

St = St−1 − βt (St−1kt − vt) ktᵀ = St−1 (I − βt ktktᵀ) + βt vtktᵀ the delta rule (Widrow & Hoff 1960; as attention: DeltaNet, Schlag et al. 2021)

Read the second form from left to right. (I − β k kᵀ) erases a fraction β of whatever S stored along the direction k, and leaves every direction orthogonal to k untouched. Then β v kᵀ writes the new value into the space just cleared. With β = 1 and a unit key the old association for k is replaced completely. That is step 3 of the worked example above: test_ch22_overwrite checks both matrices.

It is one step of gradient descent, per token

Here is the reason the delta rule is the right update and not just a patch. Treat S as a linear model and each (kt, vt) as one training example, with the squared-error loss

ℒt(S) = ½ ‖S kt − vt‖²     ∇Sℒt = (S kt − vt) ktᵀ one SGD step with learning rate βt: S ← S − βt(S kt − vt)ktᵀ, which is the delta rule

So a delta-rule layer trains a small linear regression on the fly, one example per token, and its output is that regression's prediction for the current query. test_ch22_delta_is_a_gradient_step runs autograd on ½‖Sk − v‖², takes one SGD step, and checks the result equals one step of delta_rule_recurrent to 10−12. Plain linear attention is the same picture with a worse loss: its update v kᵀ is the gradient of −⟨S k, v⟩, a loss that rewards making the output ever larger along v and never says "that is enough". This view, attention layers as test-time optimisers, is also where Titans and the "test-time training" line of work come from.

Why the keys are L2-normalised

Along k the erase factor is 1 − β‖k‖². With ‖k‖ = 1 and β ∈ (0, 1) that is in (0, 1): the old content shrinks, never flips sign or grows. With an unnormalised key of norm 2 and β = 0.9 it is −2.6, and the state explodes within a few tokens. DeltaNet and Gated DeltaNet therefore L2-normalise q and k per head, and compute β with a sigmoid. It is the same stability condition as a learning rate that must stay below 2 / (curvature) in ordinary gradient descent.

Forgetting on purpose: the gate

The delta rule can overwrite a key it is shown again, but it never forgets a key it is not. When the topic changes, old associations linger and add interference. The second ingredient is a decay αt ∈ (0, 1], also computed per token, that shrinks the whole state before the write:

St = αt St−1 (I − βt ktktᵀ) + βt vtktᵀ the gated delta rule (Yang, Kautz & Hatamizadeh 2025, "Gated Delta Networks")  ·  weight decay on the fast weights

α near 1 keeps the memory; α near 0 wipes it, which the model learns to do at document boundaries and topic shifts. In the gradient picture α is weight decay on the fast weights. The gated form is the one gated_delta_rule_recurrent implements; alpha=None gives the plain delta rule. Most of the linear-attention zoo is one row of this table, which is the most useful single thing to take from this section:

The Mamba-2 row is worth a second look. Dao and Gu (2024) showed that Mamba-2's state-space recurrence, with its scalar-times-identity transition, is gated linear attention under another name: its B, C and x play the roles of k, q and v. So "SSM versus linear attention" is not really a contest between two ideas; it is a choice of row. The rows that won in 2025 add the delta rule's error-correcting write.

Re-run the recall measurement with the delta rule (β = 1). With orthogonal keys it is exact up to n = dk, like linear attention. With random keys at n = 1024 the error is 1.35 instead of 4.01: it stops growing, because each write clears space instead of piling on. But it does not go to zero either. A dv × dk matrix has dk directions; the delta rule keeps the recent writes sharp and lets the old ones be overwritten. Hold on to that: it is the argument of §22.6.

22.5 · Training it in parallel: the chunked form

The recurrence is perfect for inference: one token in, one state update, constant memory. It is terrible for training. A 4096-token sequence is 4096 sequential steps, each a d×d matrix-vector product that is bandwidth-bound (Chapter 14) and cannot use tensor cores, and backpropagation would need the state at every step. Linear attention without the delta rule has the escape hatch of the O(T²) parallel form above. The delta rule does not: St depends on St−1 through the product St−1kt, not just a sum. Yang et al. (2024) found the way out, and it is the reason DeltaNet went from a 2021 curiosity to a 2025 production layer.

Split the sequence into chunks of C tokens (C = 64 is typical). Pass the state between chunks sequentially, and do everything inside a chunk with matmuls. The trick is to rewrite the delta rule's writes inside a chunk. Let S0 be the state entering the chunk. Each step writes a "corrected value" nt = βt(vt − St−1kt), so the state after step t is the entry state plus all corrections so far:

St = S0 + Σi≤t ni kiᵀ   ⇒   nt = βt ( vt − S0kt − Σi<t (ki·kt) ni ) each correction depends on the earlier ones only through dot products of keys

Stack the C corrections as the rows of a matrix N (C × dv). The last equation, for all t at once, is a lower-triangular linear system:

( I + diag(β) · strictly-lower(K Kᵀ) ) N = diag(β) ( V − K S0ᵀ ) a C × C unit lower-triangular matrix: solve by forward substitution (the "UT transform")

Once N is known, the outputs and the next chunk's state are plain matmuls:

O = Q S0ᵀ + ((Q Kᵀ) ⊙ M) N      SC = S0 + Nᵀ K M = causal mask including the diagonal  ·  the first term is "what the past says", the second "what this chunk said"

Look at what happened to the shapes. Every operation is (C × d) by (d × C), (C × C) by (C × d), or (C × d) by (d × d): tensor-core matmuls. The only inherently sequential piece is a C × C triangular solve per chunk, and the number of sequential steps over the sequence falls from T to T/C. With a forget gate the same derivation goes through with each term weighted by the decay accumulated between positions, gt/gi where gt = α1⋯αt inside the chunk; those ratios are at most 1, so it is computed in log space without overflow. chunked_delta_rule implements the gated version in about twenty lines:

for s in range(0, T, chunk):
    Q, K, V, b = q[s:s+chunk], k[s:s+chunk], v[s:s+chunk], beta[s:s+chunk]   # (C, dk) (C, dk) (C, dv) (C,)
    logg = torch.cumsum(torch.log(alpha[s:s+chunk]), 0)                      # (C,)    log g_t
    g = logg.exp()                                                           # (C,)
    G = (logg[:, None] - logg[None, :]).exp()                                # (C, C)  g_t / g_i
    A = I + b[:, None] * ((K @ K.T) * G * strictly_lower)                    # (C, C)  unit lower-triangular
    N = solve_triangular(A, b[:, None] * (V - g[:, None] * (K @ S.T)))       # (C, dv) corrected values
    O = g[:, None] * (Q @ S.T) + ((Q @ K.T) * G * causal) @ N                # (C, dv) outputs
    S = g[-1] * S + (N * (g[-1] / g)[:, None]).T @ K                         # (dv, dk) next chunk's state

test_ch22_chunked_equals_recurrent checks it against the token-by-token recurrence for chunk sizes 1, 7, 16, 64 and 100 on a 100-token sequence, with and without the gate, to 10−10 in float64. Production kernels (the flash-linear-attention library's Triton kernels are what Qwen3-Next and Kimi Linear ship against) do the same algebra, with more care for memory traffic and for the backward pass.

Removing the softmax from attention is what makes a fixed-size state possible. Why?
The softmax is the most expensive operation in attention
Without the softmax, attention no longer needs keys
The softmax's normaliser couples the query to every key at once; without it, Σ (q·ki) vi regroups as (Σ vikiᵀ) q, and the bracket can be accumulated once
The softmax prevents causal masking
Associativity. A dot product times a vector is a rank-1 matrix times a vector, so the sum over the past can be computed before the query arrives. With a softmax, the weight on each key depends on all the other keys' scores for this query, and nothing can be precomputed.
A delta-rule layer with β = 1 and unit keys sees key k with value (3, 1), then later sees the same key with value (−1, 4). What does it return for query k afterwards?
(2, 5): the sum of both values
(−1, 4): the old association is erased along k and replaced
(1, 2.5): the average
(3, 1): the first write wins
Erase, then write. S(I − kkᵀ) removes everything S stored along k, then v kᵀ writes the new value. (2, 5) is what plain linear attention returns, which is the bug the delta rule fixes.
In what sense is the delta rule "one step of gradient descent per token"?
The model's weights WQ, WK, WV are updated at every token during inference
It is trained with SGD instead of Adam
β is the model's learning rate
The state S is a linear model, and the update is S ← S − β ∇S ½‖S k − v‖²
The fast weights are trained, the slow weights are not. At inference only S changes. Each token is one regression example (k → v), and β is the per-token step size that the slow weights compute. Option A is the confusion this framing is designed to prevent.
What makes the chunked form fast to train, when the delta rule is a sequential recurrence?
Inside a chunk the corrected values solve one C × C lower-triangular system, and everything else is a matmul; only T/C chunk-to-chunk steps are sequential
It approximates the delta rule with linear attention inside each chunk
It runs the T steps on different GPUs in parallel
It drops the dependence of St on St−1
Exact, not approximate. The test checks chunked against recurrent to 10−10. The dependence between steps is kept; it is just expressed as dot products of keys within a chunk, which a matmul computes for all pairs at once.

22.6 · Hybrids: why some full-attention layers stay

If the delta rule is this good, why does every production model that uses it keep some softmax layers? Because of a counting argument, and a test that checks it.

The associative-recall argument

The diagnostic task is multi-query associative recall (MQAR; Arora et al. 2023, "Zoology"): the context is a list of key–value pairs, later the keys are asked for again, and the model must return each value. It is a distilled version of "what was the function name defined 40k tokens ago" or "copy this phone number from the document", and it is the skill behind in-context learning's induction heads. Arora et al. found that how well a fixed-state model does on it tracks the size of its state, and that attention solves it at any length. Jelassi et al. (2024) proved the copying version: a model with a fixed-size state cannot copy strings longer than its state can encode, while a two-layer transformer can.

Make it concrete for a real model. A Gated DeltaNet head in Qwen3-Next has a 128 × 128 state. From §22.3: at most 128 orthogonal key directions, and with n random keys the read noise of a pure sum is √((n−1)/dk). At 262,144 tokens that is √(262,143/128) ≈ 45 times the signal. The delta rule and the gate keep the noise bounded by forgetting, so the state is a sharp memory of the recent past and a blurred one of the rest. That is fine for most tokens, which need local syntax and a gist of the topic. It is not fine for the token that needs one exact fact from 200k tokens back. Softmax attention keeps every key and can sharpen onto any one of them; it is the only layer in the stack that can do an exact lookup.

The division of labour

Linear layers do the bulk sequence mixing at O(1) memory per token; a minority of full-attention layers provide the exact-lookup path. A lookup does not need to happen at every layer: the retrieved value lands in the residual stream (Chapter 4) and every later layer can read it. So the question is not "linear or attention" but "how many attention layers are enough for retrieval", and in 2025 two labs independently answered one in four.

Now the memory. bf16 KV cache for the attention layers, and assume the delta states are kept in fp32 (kernels accumulate them in fp32; qwen3_next_memory takes the state precision as an argument):

attention layers, per token:  12 × 2 × 2 KV heads × 256 × 2 bytes   = 24,576 bytes
delta states, fixed:          36 × 32 heads × 128 × 128 × 4 bytes   = 75.5 MB, for any context length

at 262,144 tokens:
  hybrid                       24,576 × 262,144 + 75.5 MB             =  6.52 GB
  same model, all 48 attention                                        = 25.77 GB   (4× more)

The fixed state costs as much as the KV cache of about 3,000 tokens, and after that it is free. Note that the saving is exactly the 3 : 1 ratio: three quarters of the layers stopped storing tokens.

Kimi Linear: 3 KDA : 1 MLA, and an ablation of the ratio

Moonshot's Kimi Linear (October 2025) is a 48B-total, 3B-active MoE that interleaves Kimi Delta Attention with MLA (Chapter 16) in what its paper calls "a uniform 3:1 ratio". KDA is the last row of the table in §22.4: Gated DeltaNet with a decay per key channel instead of one per head, so different channels of the memory can forget at different speeds. The paper reports up to 75% less KV cache (the 3 : 1 ratio again) and up to 6× decoding throughput at a 1M-token context against full MLA. Its MLA layers use no positional encoding at all (NoPE, Chapter 7): the KDA layers, being recurrences, already know the order of tokens.

The paper's ratio ablation (Table 1, validation perplexity, lower is better) is the best public evidence for "one in four":

Two things stand out. Hybrids from 1 : 1 to 7 : 1 all beat pure attention at this scale, so the linear layers are not only cheaper, they help. And quality falls off once attention becomes too rare (15 : 1), which is the associative-recall argument showing up in a perplexity number. 3 : 1 is the cheapest ratio that is still at the optimum. Treat the exact numbers as one paper's ablation at one scale, not a law.

The honest late-2026 summary

Hybrids are clearly better than pure transformers at very long context (256k+) on cost and latency, and in Kimi Linear's ablation not worse at short context either. But the largest and strongest models — DeepSeek-V3.x, Qwen3, Kimi K2.x, and the closed frontier models — remain attention-based, typically with MoE and increasingly with sparse attention. The direction of travel is clear: the 2025 hybrids from major labs chose delta-rule linear attention over Mamba-style SSMs, and both chose 3 : 1. Whether they reach the frontier depends mostly on kernels and on how they behave in long agentic contexts (§22.8), not on the mathematics, which is settled.

22.7 · Other things that are actually shipping

Multi-token prediction (MTP)

Train the model to predict the next n tokens, not just one, using extra lightweight heads. Gives a denser training signal, and at inference the extra heads act as a built-in draft model for speculative decoding — DeepSeek-V3 reports ~1.8× decoding speedup from its MTP module.

Test-time compute

The largest capability shift since instruction tuning. Instead of scaling training, spend more compute at inference: generate long chains of reasoning, sample many candidates, verify, and select. o1-style and R1-style reasoning models are trained with RL to use this budget well (Chapter 25). The scaling curve here — accuracy versus tokens-of-thinking — is a genuinely new axis, and it is currently steeper than the pretraining curve on reasoning benchmarks.

FP8 / FP4 training

DeepSeek-V3 was trained largely in FP8 with per-block scaling — a major cost reduction and one of the reasons its reported training cost was so low. Blackwell adds hardware support for even narrower formats. The engineering difficulty is entirely in the scaling strategy: which tensors need higher precision, and at what granularity.

Very large vocabularies and better tokenizers

The move to 128k–256k vocabularies (Chapter 3) continues, driven by long-context economics and multilingual coverage.

A watch item: diffusion language models

Every model in this course generates left to right, one token per forward pass (Chapter 13). Masked diffusion language models generate the other way. Training: pick a masking level t ∈ (0, 1), replace each token of the sequence with a [MASK] token independently with probability t, and train a bidirectional transformer (Chapter 9's encoder shape) to predict all the masked tokens at once, with the loss weighted by 1/t. Generation: start from an all-masked response, predict every position, keep the most confident predictions, re-mask the rest, and repeat for a fixed number of steps. With fewer steps than tokens, several tokens are committed per forward pass.

LLaDA (Nie et al. 2025) trained an 8B model this way from scratch and reported results competitive with autoregressive models of the same size; Inception Labs' Mercury and Google DeepMind's Gemini Diffusion (announced as an experimental model, May 2025) are commercial versions aimed at code, sold on speed. The open problems are the ones this course would predict: bidirectional attention defeats the KV cache (Chapter 15) as it is normally built, the number of denoising steps trades quality for speed, and variable-length output needs extra machinery. Watch it; do not plan around it yet.

22.8 · Agents: where the 2026 effort went

The largest share of 2025–26 post-training effort went not into new architectures but into making models act: call tools, read the results, and keep going for hundreds of steps. None of it needs a new layer. It needs the pieces of this course arranged differently.

Tool use is a text protocol

A tool call is ordinary generation. The chat template (Chapter 3) lists the available tools, usually as JSON schemas, in the system turn. The model emits a call between special tokens, typically a function name and JSON arguments; the runtime stops generation at the closing token, executes the call, and appends the result as a new message with a tool role; generation resumes. The Model Context Protocol (Anthropic, November 2024) standardised how a runtime discovers and calls tools, so one integration works across models. Two consequences an engineer must handle:

  • Tool output is untrusted input. A web page or file that says "ignore your instructions" arrives in the context like any other text. This is the special-token injection problem of Chapter 3 one level up: the template must make it unambiguous which tokens came from the user, the model, and the world, and the model must be trained to treat the last as data.
  • Contexts grow with every step. Each tool result is appended, so a long task reaches 100k+ tokens quickly. Every turn re-sends the whole history, which makes prefix caching (Chapter 18) the single most important serving optimisation for agents, and is one more reason the long-context architectures of §22.1–22.6 matter.

Long-horizon RL

Agents are trained with the RL machinery of Chapter 25, applied to environments instead of single answers. A rollout is a multi-turn episode: model tokens interleaved with tool results, ending in an outcome that can be checked, such as whether a repository's tests pass after the model's patch (SWE-bench Verified is the standard benchmark of this kind). Three things change from single-turn RLVR:

  • Only the model's tokens get gradient. Tool results are in the context but are masked out of the loss, exactly like the prompt in SFT (Chapter 23): the policy is not trained to predict what the compiler says.
  • Credit assignment is long. One reward at the end of a 50-turn episode has to be spread over every decision that led to it; this is where outcome versus process rewards (Chapter 25) stops being academic.
  • Rollouts are slow and uneven. An episode that runs a test suite takes minutes; lengths vary by orders of magnitude. Training systems therefore generate rollouts asynchronously from the learner, tolerating slightly stale policies, rather than in lock-step batches.

Moonshot's Kimi K2 report (subtitled "Open Agentic Intelligence") is a readable account of the full pipeline: large-scale synthesis of tool-use trajectories for SFT, then joint RL over verifiable environments.

22.9 · What has not changed since 2017

Worth stating plainly, because the pace of announcements obscures it:

  • Residual stream + attention + MLP, stacked. The skeleton is identical. Even hybrids only swap the sequence-mixing sublayer in three of every four blocks.
  • Softmax attention over query–key dot products. Every proposed replacement — linear attention, kernel methods, SSMs, the delta rule — has so far ended up supplementing it rather than replacing it, and §22.6 explains why that is not an accident.
  • Next-token prediction as the pretraining objective. Unchanged, with diffusion as the first serious alternative to watch.
  • Adam-family optimisation with warmup and decay. Muon is the first credible challenger in nine years.
  • Scaling works. Bigger, longer, more data still helps, with no clean ceiling yet observed.
How to read a new architecture paper

Ask four questions, in order: (1) Which cost does it reduce — parameters, FLOPs, memory, or bandwidth? (2) What does it give up to get that? (3) Was it validated at scale, or only at 100M parameters? (4) Is there a working kernel? An enormous number of published efficiency wins evaporate at scale or die because nobody wrote the CUDA. Chapters 13–18 give you everything you need to answer (1) and (2) from the abstract alone. Applied to the delta rule: (1) KV memory and long-context FLOPs; (2) exact recall, bought back with 1 attention layer in 4; (3) yes, two labs at 48–80B; (4) yes, the chunked kernels of §22.5.

Why is a masked diffusion language model hard to serve with a KV cache?
Its attention is bidirectional, so committing a token changes the keys and values of earlier positions; there is no append-only past to cache
It has no attention layers
It uses a different tokenizer
Its vocabulary is too large
The cache relies on causality. A decoder's position-t keys never change once computed, because nothing after t can affect them. With bidirectional attention every position sees every other, so each denoising step recomputes them. Approximate caching schemes exist; none is free.
During agentic RL, a rollout contains the model's tokens and 20k tokens of tool output. Which tokens contribute to the policy-gradient loss?
All of them, weighted equally
Only the tool outputs, since they carry the reward signal
Only the tokens the model generated; tool outputs are context, masked out of the loss
Only the final answer token
Train the policy, not the environment. Tool outputs condition the model's later tokens, but the model did not choose them, so there is no action to reinforce. Same rule as masking the prompt in SFT.
An agent framework re-sends the full conversation every turn. Which serving feature matters most for its cost?
Larger vocabularies
Prefix caching, so the shared history's KV cache is reused instead of re-prefilled each turn
Higher sampling temperature
Removing the system prompt
Most of every request is a prefix the server has already seen. Without prefix caching each turn re-prefills 100k tokens to add a few hundred; Chapter 18 covers how the cache is shared.

22.1Implement top-k sparse attentioncode

Add a DSA-style path to your attention: compute full scores, keep only the top-k per query, mask the rest to −∞, and softmax. Then, on your Chapter 11 model, measure perplexity as a function of k ∈ {8, 16, 32, 64, all} at T=128.

  1. At what k does perplexity become indistinguishable from dense?
  2. What fraction of the sequence is that?
  3. Why is this a simulation rather than a real speedup?
Discussion

You'll typically find quality saturates well before k = T — attention distributions are genuinely sparse, with most mass on a small number of positions. That empirical fact is the entire premise of sparse attention.

It's a simulation because you still computed all the scores before discarding them. A real implementation needs a cheap way to predict the top-k without computing the full score matrix — which is exactly what the lightning indexer is, and why it must be much cheaper than the attention it replaces.

22.2Attention vs a fixed state on a recall taskthinking

Design a synthetic task that isolates the difference: a sequence of random key–value pairs followed by a query for one of the keys (the MQAR task of §22.6). Train a 2-layer transformer and a 2-layer delta-rule model (use chunked_delta_rule as the sequence mixer) at sequence lengths 64, 256, 1024.

What the literature shows

The transformer solves it at all lengths — it can attend directly to the matching key. Fixed-state models degrade once the number of pairs exceeds what the state can hold, and the delta rule degrades more slowly than plain linear attention or Mamba-style gating. Adding even one attention layer largely restores performance. This experiment is the cleanest justification for hybrid architectures, and it is small enough to actually run.

22.3Read a frontier paper properlyapplied

Pick one: the DeepSeek-V3 technical report, the Kimi Linear paper, the Mamba-2 paper, or a current model's technical report. Write a one-page summary answering the four questions from §22.9's box, plus: what would you need to believe for this to not be adopted widely?

If you've worked through Chapters 1–21, the DeepSeek-V3 report should now be substantially readable — you know MLA, MoE, load balancing, FP8, MTP, and the KV-cache economics that motivate all of them. After this chapter, so should Kimi Linear's. That's a good measure of how far you've come.

22.4Build the delta rule, then make it fastcode

Without looking at tfs/linear_attention.py:

  1. Write the gated delta rule as a token-by-token recurrence for one head.
  2. Write the chunked form for the ungated case (α = 1): build A = I + diag(β)·strictly_lower(KKᵀ), solve for N, compute O and the next state.
  3. Check it against your recurrence for chunk sizes 1, 16 and T. What does chunk size 1 reduce to, and chunk size T?
  4. Time both on CPU for T = 4096, d = 64, C = 64. Then explain why the gap is much larger on a GPU.
Answer to 3 and 4

With C = 1 the system is 1 × 1 and the chunked loop is the recurrence. With C = T there is one chunk: a T × T triangular system, O(T²) memory, the delta rule's analogue of the parallel form of linear attention. Chunk sizes in between trade sequential steps (T/C) against the C² cost of the solve and the masked matmuls. On a GPU the recurrence is T bandwidth-bound matrix-vector products that cannot use tensor cores, while the chunked form is a few large matmuls per chunk, so the speedup is far larger than any CPU measurement suggests.

22.6Predict, then measure: how much can one head remember?essential

Before running anything, predict the mean relative recall error of plain linear attention with dk = 32 and n = 32, 128 and 512 random key–value pairs, using only the √((n−1)/dk) argument. Then run tfs.linear_attention.recall_error(n, 32, "linear") and the same with "delta".

  1. How close is your prediction for linear attention?
  2. Does the delta rule's error keep growing with n? Why not?
  3. Modify the experiment to measure the error separately for the first and last 10% of pairs written. What do you expect for each rule?
What you should find

Predicted √(31/32) ≈ 0.98, √(127/32) ≈ 1.99, √(511/32) ≈ 4.00; the measurements are 0.95, 2.13 and 3.99, so the law is within 10% and gets better as n grows (it is an average over many interfering pairs). The delta rule's error is 0.77, 1.17 and 1.38: it grows much more slowly, because each write first erases what the state held along the new key. Split by age at n = 512 (recall_error_by_age), linear attention is equally bad for the oldest and newest tenth (3.92 vs 4.01: a sum has no notion of time), while the delta rule recalls the newest pairs better than the oldest (0.97 vs 1.46). It is a memory weighted toward the recent past, which is the property the hybrid design relies on.
