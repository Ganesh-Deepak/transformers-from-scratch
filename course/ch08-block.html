8 · The Transformer Block

Attention lets tokens talk to each other, and that is half of a transformer. The other half, which holds about two-thirds of the parameters, is an MLP applied to each token. This chapter puts both together into the block that gets stacked 32, 80 or 120 times, and explains every design choice that has changed since 2017.

Ch 06 — the attention sublayer
Leads toCh 09 — stack this and you have a model
Ch 20 — MoE replaces exactly this chapter's MLP

The whole chapter in five sentences

A block is attention (tokens talk) followed by an MLP (each token thinks). Each runs on a normalised copy of the residual stream, and each adds its result back to it. RMSNorm before each sublayer keeps the residual path clean and lets models train to more than 100 layers. The MLP holds about two-thirds of the parameters and FLOPs; SwiGLU's gate is the modern choice, with d_ff ≈ 8/3·d_model. At scale, attention logits grow with the square of the weights until the softmax saturates and training spikes, and QK-norm and sandwich norms exist to stop that. Each block's cost can be counted: about 2 FLOPs per weight per token, and tens of bytes of saved activations per token per feature for the backward pass.

8.1 · The block, in four lines

def block(x):
    x = x + attn(norm1(x))       # tokens exchange information
    x = x + mlp (norm2(x))       # each token thinks on its own
    return x

There are two sublayers, each wrapped in norm → sublayer → add. The shape is (B, T, C) at every step.

The division of labour

Attention moves information between positions. It is the only part of the model where token i can see token j. The MLP transforms information within a position. It processes every token the same way and separately, and it cannot see other tokens at all. Communicate, then compute, then repeat.

8.2 · Normalisation: LayerNorm vs RMSNorm

LayerNorm (Ba et al. 2016)

LN(x) = x − μ√(σ² + ε) ⊙ γ + β     μ, σ² computed over the last axis only 
class LayerNorm(nn.Module):
    def __init__(self, d, eps=1e-5):
        super().__init__()
        self.g = nn.Parameter(torch.ones(d))       # scale γ
        self.b = nn.Parameter(torch.zeros(d))      # shift β
        self.eps = eps

    def forward(self, x):                          # x: (B, T, C)
        mu  = x.mean(-1, keepdim=True)             # (B, T, 1)
        var = x.var(-1, keepdim=True, unbiased=False)
        return (x - mu) / torch.sqrt(var + self.eps) * self.g + self.b
LayerNorm ≠ BatchNorm

BatchNorm normalises across the batch for each feature, while LayerNorm normalises across features for each token. So LayerNorm's statistics do not depend on other examples. That is why it works with a batch size of 1, works at inference without running averages, and works with sequences of different lengths. BatchNorm would be a disaster in an autoregressive model.

RMSNorm (Zhang & Sennrich 2019) — what modern models use

RMSNorm(x) = x√(mean(x²) + ε) ⊙ γ no mean subtraction, no bias term 
class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__()
        self.g = nn.Parameter(torch.ones(d))
        self.eps = eps

    def forward(self, x):
        # cast to fp32 for the reduction — this matters in bf16 training
        rms = x.float().pow(2).mean(-1, keepdim=True).add(self.eps).rsqrt()
        return (x.float() * rms).type_as(x) * self.g

RMSNorm drops the mean subtraction and the bias. Experiments found that re-centring does almost nothing, and only re-scaling matters. You get fewer parameters, one fewer pass over the data to compute a statistic, and layers ~7 to 15% faster at equal quality. Llama, Mistral, Qwen, Gemma, DeepSeek and nearly every model since 2023 use it.

Worked example — both norms on the same 4 numbers

One token, d_model = 4, with vector x = [3, 1, 4, 8], and with γ = 1 and β = 0 so that you see the maths and not the parameters.

out   = [-0.392, -1.177, 0.000, 1.569]

check: mean(out) = 0.000   std(out) = 1.000

mean(x²) = (9 + 1 + 16 + 64) / 4 = 22.5
rms      = sqrt(22.5) = 4.7434

3
What it saved. RMSNorm skipped one full pass over the data (the mean) and one subtraction per element, and it drops β entirely: d_model fewer parameters per norm, with two norms per block, in every layer.
4
How different are the two outputs? On this vector, quite different: cosine similarity is only 0.54. That is because [3,1,4,8] has a mean of 4 — large relative to its spread — and centring matters most exactly when the mean is large.

Real activations are not like that. At d_model = 768, with activations of roughly zero mean, the median cosine similarity between the LayerNorm and RMSNorm outputs is 0.9997 (measured over 2000 random vectors; the worst case was 0.994). Push the mean away from zero by 2σ and it drops to 0.45.

That is the experimental argument, and the condition it depends on. Zhang & Sennrich found that re-scaling is what stabilises training while re-centring adds almost nothing, because trained activations sit near zero mean. Drop the centring and you lose nothing you were using. The toy vector above is a deliberate counter-example that shows the case where that assumption would break.

import torch
x = torch.tensor([3., 1., 4., 8.])

mu, var = x.mean(), x.var(unbiased=False)
ln = (x - mu) / torch.sqrt(var + 1e-5)
rms = x * torch.rsqrt(x.pow(2).mean() + 1e-5)

print(ln.round(decimals=3))    # [-0.392, -1.177,  0.000,  1.569]
print(rms.round(decimals=3))   # [ 0.632,  0.211,  0.843,  1.687]
print("LN   mean/std:", ln.mean().item(), ln.std(unbiased=False).item())
print("RMS  mean/rms:", rms.mean().item(), rms.pow(2).mean().sqrt().item())
print("cosine:", torch.nn.functional.cosine_similarity(ln, rms, dim=0).item())
Try it Add a constant to every element of x. LayerNorm's output is unchanged, because it ignores shifts. RMSNorm's output moves. The experiments say that difference does not matter in practice.

Pre-LN vs Post-LN — a change that mattered a lot

Post-LN (original, 2017) 
x = norm(x + attn(x))
x = norm(x + mlp(x))

The norm sits on the residual path. Gradients have to pass through a normalisation in every layer, so they get rescaled again and again. Deep post-LN models will not train without a careful learning-rate warmup, and beyond ~20 layers they often diverge anyway.

Pre-LN (modern default) 
x = x + attn(norm(x))
x = x + mlp(norm(x))

The norm sits on the branch, which leaves the residual path completely clean: ∂x_out/∂x_in still contains an exact identity term. It trains stably to more than 100 layers, tolerates larger learning rates and needs much less warmup.

One consequence of pre-LN is that the residual stream is never normalised, so its size grows with depth. That is why pre-LN models need a final norm after the last block, before the LM head. Forgetting it is a classic bug.

Where normalisation placement is in 2026

Pre-LN is the default, but several 2024 to 2025 models added extra norms for stability at scale. Gemma 2 and 3 use a "sandwich" (a norm before and after each sublayer), OLMo 2 moved to a post-norm variant applied to the branch output, and QK-norm (normalising q and k before the dot product) has become common, because it directly prevents the attention-logit blow-ups that cause loss spikes in large runs. The trend is toward more normalisation, placed off the residual path.

8.3 · The MLP — where the parameters actually live

class MLP(nn.Module):
    def __init__(self, d_model, d_ff):
        super().__init__()
        self.up   = nn.Linear(d_model, d_ff)      # (B,T,C) → (B,T,d_ff)
        self.down = nn.Linear(d_ff, d_model)      # (B,T,d_ff) → (B,T,C)
    def forward(self, x):
        return self.down(F.gelu(self.up(x)))

Expand to d_ff = 4·d_model, apply a non-linearity, and project back. Every token goes through this separately: it is a per-position function, applied B×T times in parallel.

Two-thirds of the model is here

Per layer, with d_ff = 4C and no biases:

  • Attention: 4C² (W_q, W_k, W_v, W_o)
  • MLP: 8C² (up is C×4C, down is 4C×C)
  • Total 12C² per layer, so the MLP is 2× the size of attention.

A useful sanity check: a transformer's parameter count is roughly 12 · n_layer · d_model² plus embeddings. For GPT-2 small: 12 × 12 × 768² ≈ 85M, plus 38.6M of embeddings ≈ 124M, which is exactly right.

What does the MLP do?

The best current answer comes from interpretability: the MLP works like a key-value memory. The first matrix's rows are detectors, so each neuron fires on a particular pattern in the residual stream, and the second matrix's columns are what gets written back when that neuron fires. Geva et al. (2021) showed that you can read these off directly: particular neurons fire on "text about sports", "the token is a date", and so on.

Activation functions: ReLU → GELU → SwiGLU

class SwiGLU(nn.Module):
    def __init__(self, d_model, d_ff):
        super().__init__()
        self.gate = nn.Linear(d_model, d_ff, bias=False)
        self.up   = nn.Linear(d_model, d_ff, bias=False)
        self.down = nn.Linear(d_ff, d_model, bias=False)
    def forward(self, x):
        return self.down(F.silu(self.gate(x)) * self.up(x))
        #                 ^^^^^^^^^^^^^^^^^^^^^ the GATE: a learned, per-neuron
        #                 multiplicative filter on the up-projection
Why 8/3 keeps showing up

SwiGLU uses three matrices instead of two, so at the same d_ff it would have 1.5× the parameters. To keep the comparison fair, implementations shrink d_ff by 2/3: d_ff = (8/3)·d_model instead of 4·d_model. Llama-2-7B has d_model=4096 and d_ff=11008, which is 2.6875×: 8/3 rounded to a multiple of 256 for hardware alignment. That is why you see odd-looking numbers like 11008 and 14336.

Noam Shazeer's paper introducing GLU variants ends with the line "We offer no explanation as to why these architectures seem to work; we attribute their success, as all else, to divine benevolence." That is a real quote, and it honestly describes how much anyone understands about activation functions.

8.4 · Dropout — mostly gone

The original transformer used dropout 0.1 everywhere. Modern LLM pretraining usually sets it to zero. Dropout is a regulariser for when data is scarce, and when you train on 15 trillion tokens with 8 billion parameters you are nowhere near overfitting; you are under-fitting. Dropout would only slow you down.

It comes back during fine-tuning on small datasets, where overfitting is a real risk again.

8.5 · The complete block

class Block(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.n1   = RMSNorm(cfg.d_model)
        self.attn = MultiHeadAttention(cfg)
        self.n2   = RMSNorm(cfg.d_model)
        self.mlp  = SwiGLU(cfg.d_model, cfg.d_ff)

    def forward(self, x, freqs=None, kv_cache=None):
        x = x + self.attn(self.n1(x), freqs, kv_cache)     # (B, T, C)
        x = x + self.mlp (self.n2(x))                      # (B, T, C)
        return x

8.6 · Logit growth, and the norms that stop it

Pre-LN fixed the instability of 2017. Training models with tens of billions of parameters revealed a second instability, and it has the same mathematical shape as the √dk argument of Chapter 5, taken one step further. Here it is in four steps.

1. Logits grow with the square of the weights. An attention logit is (x WQ)·(x WK) / √d. The input x is normalised, so its scale is fixed. But if training lets the norms of WQ and WK each grow by a factor g, every logit grows by g². Nothing in a pre-LN block pushes back, because the normalisation comes before the projections, not after them.

2. Large logits saturate the softmax. tfs.foundations.softmax_saturation draws 64 logits from a standard normal distribution, multiplies them by a scale, and measures the attention distribution:

logit scale(weights grown by)entropy (nats; max ln 64 = 4.16)largest weightsoftmax Jacobian, RMS

21.4×2.080.510.039
42×0.440.920.013

164×0.0001.000< 10−5

Doubling the projection weights takes a head from spreading its attention over many keys to putting 92% on one. Quadrupling them turns it into a hard argmax.

3. A saturated softmax has no gradient. The last column is the size of the softmax's Jacobian, diag(p) − p pᵀ. Once one weight is ≈ 1, every entry of the Jacobian is ≈ 0, so no gradient reaches the logits and the head cannot learn its way out. It stays stuck on whatever key it locked onto.

4. Saturated heads cause loss spikes. A head stuck on one key copies that key's value at full strength, and when the key changes (a new batch, a new document), its output jumps abruptly. Dehghani et al. (2023) hit exactly this while training ViT-22B: the attention logits grew without limit and training diverged. Wortsman et al. (2023) reproduced the same instability in small models trained at high learning rates, which made it cheap to study, and showed that the fix below removes it.

QK-norm

Normalise each head's q and k after the projection (Chapter 5 §5.10): q̂ = RMSNorm(q) and k̂ = RMSNorm(k), each with its own learned gain. Now growing WQ changes the direction of q but not its length, and the scaled logit is bounded by √d · gqgk, which is 11.3 for d = 128 at unit gains. Only the gains, a few parameters per head, can sharpen attention, and weight decay keeps them modest. It costs two tiny norms per head and is now standard (OLMo 2, Gemma 3, Qwen3).

Sandwich norm and output norms

The same reasoning applied to the residual stream gives the other change from 2024 to 2025. In pre-LN, a sublayer's input is normalised but its output is not, so one block whose output grows large can dominate the stream for every block after it (and Chapter 4 showed that the stream already grows with depth). Sandwich norm (Gemma 2 and 3) normalises both:

x = x + norm_post_attn(attn(norm_pre_attn(x)))       # the branch output has RMS ≈ its gain
x = x + norm_post_mlp(mlp(norm_pre_mlp(x)))

OLMo 2 keeps only the second norm of each pair (x = x + norm(attn(x))) and adds QK-norm. Either way, the residual path itself stays unnormalised, so the identity path for gradients from §8.2 is untouched; what is limited is how much any single sublayer can write into the stream per step. "More normalisation, placed off the residual path" (the box above) is this argument in one line.

8.7 · Parallel blocks: attention and MLP side by side

The block in §8.5 is serial: the MLP reads the stream after attention has written to it. GPT-J (2021) and PaLM (2022) used a parallel form instead, where both sublayers read the same normalised input and their outputs are added together:

class ParallelBlock(nn.Module):                     # tfs.foundations.ParallelBlock
    def forward(self, x, cos, sin):
        h = self.n(x)                               # ONE norm, shared
        a, _ = self.attn(h, cos, sin)
        return x + a + self.mlp(h)                  # both read h; neither sees the other's output

Why do it? The two input projections (attention's Q, K and V, and the MLP's up and gate) now multiply the same h, so they can be fused into one larger matmul, and the two sublayers can run at the same time. The PaLM paper reports roughly 15% faster training at large scale, with a small loss of quality at 8B parameters and none at 62B. It also saves one norm per block. Falcon and GPT-NeoX-20B used it too.

Why did it fall out of use? The Llama family (2023 onward), Mistral, Qwen, DeepSeek and most later open models are serial. The published evidence says parallel blocks cost a little quality at the scales most models are trained at. A plausible reason the speed gain stopped being worth it is that at modern widths each sublayer's matmuls are already large enough to keep a GPU busy on their own, so fusing them gains less. The serial block also has a clean meaning that the parallel one lacks: the MLP can work on what attention just retrieved in the same layer. Treat the parallel block as a well-documented design option, not a mistake.

8.8 · A per-block budget: FLOPs, and what backward has to keep

Everything in a block can be counted. Start with FLOPs: 2 per weight per token, plus attention's own two matmuls. For Llama-2-7B's block (d = 4096, 32 heads of 128, no GQA, SwiGLU with d_ff = 11008) at T = 4096 with a causal mask (tfs.foundations.block_flops_per_token):

Q and O projections   2 × 2 × 4096 × 4096       =  67.1 M FLOPs per token
K and V projections   2 × 2 × 4096 × 4096       =  67.1 M
MLP (3 matrices)      2 × 3 × 4096 × 11008      = 270.5 M      61.7% of the block
scores + mix          2 × 2 × 4096 × 4096 / 2   =  33.6 M      (causal: half the keys on average)
total                                           = 438.3 M FLOPs per token, forward

Training costs about three times as much (Chapter 2). The MLP is the largest item until T gets close to 6·d.

Memory is the less obvious budget. The backward pass needs the inputs of every matmul and the outputs of several nonlinearities, so the forward pass must save them. Korthikanti et al. (2022) counted them for a GPT-style block (a 4h GELU MLP, dropout, 16-bit activations, no recomputation). Per layer, with sequence length s, micro-batch b, hidden size h and a heads:

activations per layer = s·b·h·(34 + 5·a·s / h) bytes 34·sbh: the matmul inputs, norm inputs, GELU input, dropout masks  ·  5·a·s²·b: the attention score, softmax and dropout matrices

For a 7B-class layer (h = 4096, a = 32) at s = 4096 and b = 1 (activation_bytes_per_layer):

34 · s · b · h        =  0.57 GB
5 · a · s² · b        =  2.68 GB         the T × T matrices dominate
per layer             =  3.25 GB    × 32 layers = 104 GB, for ONE sequence
with FlashAttention   =  0.57 GB    × 32 layers =  18 GB  (scores are recomputed in backward, not stored)

That is why FlashAttention matters for training memory, not only for speed (Chapter 17). Even 18 GB per sequence is too much at real batch sizes, and the remaining fix is activation checkpointing: store only each block's input and recompute the rest during backward, which costs roughly one extra forward pass and saves most of this memory. Chapter 10 derives what is saved and why, and Chapter 19 sets the policy at scale. (The 34 is specific to Korthikanti's block; SwiGLU, no dropout and RMSNorm change the number, and the exercise below has you recount it.)

Why can a parallel block fuse attention's and the MLP's input projections into one matmul, when a serial block cannot?
Parallel blocks have fewer parameters
Serial blocks use GQA
The MLP has no weights in a parallel block

8.9 · Exercises

8.1Implement and verify both normswarm-up

Write LayerNorm and RMSNorm from scratch, and check your LayerNorm against nn.LayerNorm. Then, on a random (4, 128, 512) input, measure:

  1. The mean and std of each output along the last axis.
  2. The wall-clock time for 1000 forward passes of each.
  3. The cosine similarity between the two outputs.
Expected

LayerNorm's output has mean ≈ 0 and std ≈ 1 exactly. RMSNorm's output has std ≈ 1, but its mean is whatever the input's mean was (scaled). The cosine similarity between them is usually > 0.98 for random input: they do nearly the same thing, which is the experimental point. RMSNorm is usually 20 to 40% faster in a pure-Python benchmark, and less in a fused kernel.

8.2Pre-LN vs post-LN, measuredessential

Build a 24-layer transformer both ways. Without training, do one forward and backward pass on random data and plot block[i].attn.qkv.weight.grad.norm() against the layer index i for both, on a log scale.

What you'll see

Post-LN gradients are largest at the top and shrink toward layer 0; in the companion notebook's 24-layer model the ratio is about 5 to 10×. (Much larger ratios, 103 and up, usually come from initialisation rather than depth: a tiny raw embedding that feeds layer 0 alone.) Pre-LN gradients are roughly flat across depth. Then try training both with the same learning rate: post-LN will spike or diverge, and pre-LN will not. This one plot explains a design decision that took the field about two years to settle.

8.3Match SwiGLU parameters to GELUcode

Write swiglu_ff_dim(d_model, multiple_of=256), which returns the d_ff that gives a SwiGLU MLP the same parameter count as a GELU MLP with d_ff = 4·d_model, rounded up to a multiple of multiple_of. Check that it gives 11008 for d_model=4096.

Solution
def swiglu_ff_dim(d_model, multiple_of=256):
    hidden = 4 * d_model
    hidden = int(2 * hidden / 3)                       # 3 matrices instead of 2
    return multiple_of * ((hidden + multiple_of - 1) // multiple_of)

swiglu_ff_dim(4096)     # 11008  ✓  (matches Llama-2-7B)
swiglu_ff_dim(8192)     # 22016  ✓  (matches Llama-2-70B... almost — see below)

This is almost exactly Meta's own function. Note that Llama-2-70B actually uses d_ff=28672, because it applies an extra ffn_dim_multiplier=1.3. Real configs depart from clean formulas, so always read the config file instead of assuming.

8.4Find what MLP neurons detectexploration

Load GPT-2 and pick layer 6. Run a few hundred sentences through it and record the post-activation value of neuron k in the MLP hidden layer for every token. Find the 20 tokens (with their context) that activate it most. Repeat for 10 random neurons.

What you'll find

Some neurons are very easy to interpret: one fires on tokens inside quoted speech, another on the second half of hyphenated words, another on numerals in dates. Many others look like noise. They are polysemantic: they fire on several unrelated concepts because the model packs more features into d_ff neurons than it has neurons. That effect, superposition, is what sparse autoencoders were invented to untangle, and it is at the frontier of interpretability research.

gate output (SiLU's input)      d_ff       = 14336
up output                       d_ff       = 14336
down projection's input         d_ff       = 14336
                                total      ≈ 69,700 elements ≈ 139 KB per token per layer (bf16)
                                           ≈ 34·h bytes per token, coincidentally close to Korthikanti's 34

Implementations differ (some recompute SiLU instead of storing both its input and output, and some store the normalised x once). What matters is the method: walk through the forward pass and write down what each backward step needs. At 8,192 tokens and 32 layers that comes to about 36 GB per sequence, which is why checkpointing is required for long-context training.

8.6Predict, then measure: QK-norm bounds the logitscode

Add QK-norm to tfs.model.GroupedQueryAttention (an RMSNorm(d_head) on q and on k, before RoPE). Then, on a randomly initialised model, multiply every q_proj and k_proj weight by 1, 2, 4 and 8, and record the maximum attention logit and the mean attention entropy of layer 0, with and without QK-norm. Predict both curves before you run it.

What you should see

Without QK-norm the maximum logit grows like the square of the multiplier (×64 at 8×), and the entropy collapses as in the table in §8.6. With QK-norm both stay flat: the multiplier changes nothing at all, because RMSNorm divides it out. The maximum logit stays below √dhead at unit gains. It also makes an easy regression test to keep in a training codebase.

8.7Serial versus parallel, on the same budgetexploration

Build two 4-layer models, one from tfs.model.Block and one from tfs.foundations.ParallelBlock, with identical widths. Train both on the same data for the same number of steps, and compare validation loss and step time. Then fuse the parallel block's attention and MLP input projections into one Linear and time it again.

What to expect

At this scale the parallel model is usually slightly worse per step, which matches PaLM's observation at 8B, and the fused version is faster per step on a GPU; on a CPU the speed difference is small. Whether the trade is worth it depends on which you are short of, time or quality. Make sure both models have the same norm parameters, or the comparison is not fair.
