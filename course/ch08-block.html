8 · The Transformer Block

Attention lets tokens talk to each other. That's half a transformer. The other half — the part with about two-thirds of the parameters — is a per-token MLP. This chapter assembles both into the block that gets stacked 32, 80, or 120 times, and explains every design choice that has changed since 2017.

8.1 · The block, in four lines

def block(x):
    x = x + attn(norm1(x))       # tokens exchange information
    x = x + mlp (norm2(x))       # each token thinks on its own
    return x

That's it. Two sub-layers, each wrapped in norm → sublayer → add. Shape is (B, T, C) at every step.

The division of labour

Attention moves information between positions. It's the only part of the model where token i can see token j. The MLP transforms information within a position. It processes every token identically and independently — it literally cannot see other tokens. Communicate, then compute. Repeat.

8.2 · Normalisation: LayerNorm vs RMSNorm

LayerNorm (Ba et al. 2016)

LN(x) = x − μ√(σ² + ε) ⊙ γ + β     μ, σ² computed over the last axis only 
class LayerNorm(nn.Module):
    def __init__(self, d, eps=1e-5):
        super().__init__()
        self.g = nn.Parameter(torch.ones(d))       # scale γ
        self.b = nn.Parameter(torch.zeros(d))      # shift β
        self.eps = eps

    def forward(self, x):                          # x: (B, T, C)
        mu  = x.mean(-1, keepdim=True)             # (B, T, 1)
        var = x.var(-1, keepdim=True, unbiased=False)
        return (x - mu) / torch.sqrt(var + self.eps) * self.g + self.b
LayerNorm ≠ BatchNorm

BatchNorm normalises across the batch for each feature; LayerNorm normalises across features for each token. LayerNorm's statistics therefore don't depend on other examples — which is why it works with batch size 1, works at inference without running averages, and works with variable sequence lengths. BatchNorm would be a disaster in an autoregressive model.

RMSNorm (Zhang & Sennrich 2019) — what modern models use

RMSNorm(x) = x√(mean(x²) + ε) ⊙ γ no mean subtraction, no bias term 
class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__()
        self.g = nn.Parameter(torch.ones(d))
        self.eps = eps

    def forward(self, x):
        # cast to fp32 for the reduction — this matters in bf16 training
        rms = x.float().pow(2).mean(-1, keepdim=True).add(self.eps).rsqrt()
        return (x.float() * rms).type_as(x) * self.g

RMSNorm drops the mean subtraction and the bias. The empirical finding was that re-centering does almost nothing; only re-scaling matters. You get fewer parameters, one less reduction pass over the data, and ~7–15% faster layers at equal quality. Llama, Mistral, Qwen, Gemma, DeepSeek, and essentially every model since 2023 use it.

Pre-LN vs Post-LN — a change that mattered a lot

Post-LN (original, 2017) 
x = norm(x + attn(x))
x = norm(x + mlp(x))

The norm sits on the residual path. Gradients must pass through a normalisation on every layer, so they get rescaled repeatedly. Deep post-LN models will not train without a careful learning-rate warmup, and beyond ~20 layers they often diverge anyway.

Pre-LN (modern default) 
x = x + attn(norm(x))
x = x + mlp(norm(x))

The norm sits on the branch, leaving the residual highway completely clean — ∂x_out/∂x_in still contains an exact identity term. Trains stably to 100+ layers, tolerates larger learning rates, and needs much less warmup.

One consequence of pre-LN: the residual stream is never normalised, so its magnitude grows with depth. That's why pre-LN models need a final norm after the last block, before the LM head. Forgetting it is a classic bug.

Where normalisation placement is in 2026

Pre-LN is the default, but several 2024–2025 models added extra norms for stability at scale: Gemma 2/3 use a "sandwich" (norm before and after each sublayer), OLMo 2 moved to a post-norm variant applied to the branch output, and QK-norm (normalising q and k before the dot product) has become common — it directly prevents the attention-logit explosions that cause loss spikes in large runs. The direction of travel is "more normalisation, placed off the residual path."

8.3 · The MLP — where the parameters actually live

class MLP(nn.Module):
    def __init__(self, d_model, d_ff):
        super().__init__()
        self.up   = nn.Linear(d_model, d_ff)      # (B,T,C) → (B,T,d_ff)
        self.down = nn.Linear(d_ff, d_model)      # (B,T,d_ff) → (B,T,C)
    def forward(self, x):
        return self.down(F.gelu(self.up(x)))

Expand to d_ff = 4·d_model, apply a non-linearity, project back. Every token goes through this independently — it is a per-position function, applied B×T times in parallel.

Two-thirds of the model is here

Per layer, with d_ff = 4C and no biases:

  • Attention: 4C² (W_q, W_k, W_v, W_o)
  • MLP: 8C² (up is C×4C, down is 4C×C)
  • Total 12C² per layer — the MLP is 2× the attention.

A useful sanity check: a transformer's parameter count is roughly 12 · n_layer · d_model² plus embeddings. For GPT-2 small: 12 × 12 × 768² ≈ 85M, plus 38.6M embedding ≈ 124M. That is exactly right.

What does the MLP do?

The best current answer comes from interpretability: the MLP acts as a key–value memory. The first matrix's rows are "detectors" — each neuron fires on a particular pattern in the residual stream; the second matrix's columns are what gets written back when that neuron fires. Geva et al. (2021) showed you can read these off directly: specific neurons fire on "text about sports", "the token is a date", and so on.

class SwiGLU(nn.Module):
    def __init__(self, d_model, d_ff):
        super().__init__()
        self.gate = nn.Linear(d_model, d_ff, bias=False)
        self.up   = nn.Linear(d_model, d_ff, bias=False)
        self.down = nn.Linear(d_ff, d_model, bias=False)
    def forward(self, x):
        return self.down(F.silu(self.gate(x)) * self.up(x))
        #                 ^^^^^^^^^^^^^^^^^^^^^ the GATE: a learned, per-neuron
        #                 multiplicative filter on the up-projection
Why 8/3 keeps showing up

SwiGLU uses three matrices instead of two, so at the same d_ff it would have 1.5× the parameters. To keep the comparison fair, implementations shrink d_ff by 2/3: d_ff = (8/3)·d_model instead of 4·d_model. Llama-2-7B has d_model=4096 and d_ff=11008 — that's 2.6875×, i.e. 8/3 rounded to a multiple of 256 for hardware alignment. When you see an odd number like 11008 or 14336, this is why.

Noam Shazeer's paper introducing GLU variants ends with the line "We offer no explanation as to why these architectures seem to work; we attribute their success, as all else, to divine benevolence." That is a real quote, and it's an honest summary of the state of activation-function research.

Why does RMSNorm work as well as LayerNorm despite dropping the mean subtraction?
The mean is always zero in practice
The residual connection already centers the data
Empirically, re-scaling provides the training stability; re-centering contributes little
RMSNorm actually performs worse, but is used because it's faster
Re-scaling is the active ingredient. Zhang & Sennrich ablated this directly: the invariance that matters for optimisation is to the scale of the input, not its offset. Dropping the mean gives you one fewer reduction and 2 fewer parameters per feature at equal quality — a free win, which is why adoption was near-universal.
A 48-layer post-LN transformer diverges during training. Switching to pre-LN fixes it. Why?
Pre-LN keeps the residual path free of normalisation, so gradients have an unscaled identity route to every layer
Pre-LN has fewer parameters
Pre-LN uses a smaller learning rate automatically
Post-LN can't represent as many functions
The gradient highway. In post-LN, every backward step passes through a norm's Jacobian, and those compound across 48 layers. In pre-LN, ∂(x + f(norm(x)))/∂x = I + … — the identity survives untouched. Both can represent the same functions; only one is optimisable at depth.

≈ 4.3B. Three matrices of 4096×11008 = 45.09M each → 135.3M per layer × 32 layers = 4.33B. Out of 6.7B total, that's 65% of the model in the MLPs — confirming the "two-thirds" rule of thumb. This is also why MoE (Chapter 16) targets the MLP and not attention.

8.4 · Dropout — mostly gone

The original transformer used dropout 0.1 everywhere. Modern LLM pretraining usually sets it to zero. The reason is simple: dropout is a regulariser for the small-data regime, and when you train on 15 trillion tokens with 8 billion parameters you are nowhere near overfitting — you're under-fitting. Dropout would just slow you down.

It reappears during fine-tuning on small datasets, where overfitting is real again.

8.5 · The complete block

class Block(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.n1   = RMSNorm(cfg.d_model)
        self.attn = MultiHeadAttention(cfg)
        self.n2   = RMSNorm(cfg.d_model)
        self.mlp  = SwiGLU(cfg.d_model, cfg.d_ff)

    def forward(self, x, freqs=None, kv_cache=None):
        x = x + self.attn(self.n1(x), freqs, kv_cache)     # (B, T, C)
        x = x + self.mlp (self.n2(x))                      # (B, T, C)
        return x

8.6 · Exercises

8.1Implement and verify both normswarm-up

Write LayerNorm and RMSNorm from scratch. Verify your LayerNorm against nn.LayerNorm. Then, on a random (4, 128, 512) input, measure:

  1. The mean and std of each output along the last axis.
  2. Wall-clock time for 1000 forward passes of each.
  3. Cosine similarity between the two outputs.
Expected

LayerNorm output has mean ≈ 0, std ≈ 1 exactly. RMSNorm output has std ≈ 1 but mean ≈ whatever the input's mean was (scaled). The cosine similarity between them is typically > 0.98 for random input — they are doing nearly the same thing, which is the empirical point. RMSNorm is usually 20–40% faster in a pure-Python benchmark, less in a fused kernel.

8.2Pre-LN vs post-LN, measuredessential

Build a 24-layer transformer both ways. Without training, do one forward+backward on random data and plot block[i].attn.qkv.weight.grad.norm() against layer index i for both, on a log scale.

What you'll see

Post-LN gradients decay roughly geometrically with depth — often 2–4 orders of magnitude smaller at layer 0 than at layer 23. Pre-LN gradients are approximately flat across depth. Then try actually training both with the same LR: post-LN will spike or diverge, pre-LN won't. This single plot explains a design decision that took the field about two years to settle.

8.3Match SwiGLU parameters to GELUcode

Write swiglu_ff_dim(d_model, multiple_of=256) that returns the d_ff making a SwiGLU MLP have the same parameter count as a GELU MLP with d_ff = 4·d_model, rounded up to a multiple of multiple_of. Verify it gives 11008 for d_model=4096.

Solution
def swiglu_ff_dim(d_model, multiple_of=256):
    hidden = 4 * d_model
    hidden = int(2 * hidden / 3)                       # 3 matrices instead of 2
    return multiple_of * ((hidden + multiple_of - 1) // multiple_of)

swiglu_ff_dim(4096)     # 11008  ✓  (matches Llama-2-7B)
swiglu_ff_dim(8192)     # 22016  ✓  (matches Llama-2-70B... almost — see below)

This is essentially Meta's own function. Note Llama-2-70B actually uses d_ff=28672, because it applies an extra ffn_dim_multiplier=1.3. Real configs deviate from clean formulas — always read the config file rather than assuming.

8.4Find what MLP neurons detectexploration

Load GPT-2. Pick layer 6. Run a few hundred sentences through it and record the post-activation value of neuron k in the MLP hidden layer for every token. Find the 20 tokens (with context) that maximally activate it. Repeat for 10 random neurons.

What you'll find

Some neurons are strikingly interpretable — one fires on tokens inside quoted speech, another on the second half of hyphenated words, another on numerals in dates. Many others look like noise: they're polysemantic, firing on several unrelated concepts because the model is packing more features into d_ff neurons than it has neurons. That phenomenon — superposition — is what sparse autoencoders were invented to untangle, and it's the frontier of interpretability research.
