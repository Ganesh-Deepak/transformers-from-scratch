4 · Embeddings and the Residual Stream

Two ideas here. The first is mechanical and easy: an embedding is a lookup table. The second is the most useful mental model in this entire course — the residual stream — and it is what turns a transformer from "a stack of mystery boxes" into something you can reason about.

4.1 · An embedding is a lookup, not a matmul

nn.Embedding(V, C) holds a single weight matrix of shape (V, C): one row per vocabulary entry, each row a C-dimensional vector.

import torch, torch.nn as nn

V, C = 50257, 768
emb = nn.Embedding(V, C)
emb.weight.shape                  # (50257, 768)  → 38.6M parameters

ids = torch.tensor([[15496, 995, 0],
                    [  464, 3797, 3332]])    # (B=2, T=3)
x = emb(ids)
x.shape                           # (2, 3, 768)   ← (B, T, C)
What just happened, shape-wise

Every integer in a (B, T) tensor was replaced by a vector of length C. So the rank went up by one and the last axis appeared: (B, T) → (B, T, C). This is the only place in the whole model where the rank increases like this. From here to the very end, the shape stays (B, T, C).

It is equivalent to a one-hot matmul (but never implemented that way)

onehot(i)  ·  WE  =  row i of WE (1, V) @ (V, C) → (1, C) 
# These are numerically identical:
onehot = torch.zeros(1, V); onehot[0, 15496] = 1.0
(onehot @ emb.weight)          # (1, 768)  — 50257 multiplies, 50256 of them by zero
emb.weight[15496]              # (768,)    — one memory read
Worked example — the same answer, two ways

A toy table: vocabulary of 6, embedding dimension 4.

As a matmul. One-hot for token 3 is [0,0,0,1,0,0]:

As a lookup. W[3] → [1.2, 1.3, 1.4, 1.5]. Identical, and it read four numbers instead of doing 24 multiplies.
4
Count the waste. 20 of the 24 multiplies were by zero — 83%. Now scale to GPT-2: 
matmul: 50,257 × 768 = 38,597,376 multiplies, 50,256 rows of them by zero
lookup:                            768 memory reads

50,257× more arithmetic for the same answer.

Two things follow from this. (1) An embedding is a linear layer — which is why weight tying with the output projection is even coherent. (2) The gradient reaches exactly one row per token occurrence, because every other row was multiplied by zero. That sparsity is precisely the mechanism behind the under-trained "glitch tokens" of Chapter 3: a token seen once gets one gradient update, ever.

The one-hot view is conceptually useful (it explains why an embedding layer is a linear layer, and why gradients flow to exactly one row per token). The lookup view is what actually runs.

Consequence: embeddings are sparse to train

Each training step only updates the rows for tokens that actually appeared in the batch. A token appearing once in 10 billion gets one gradient update, ever — which is precisely the mechanism behind the under-trained "glitch tokens" from Chapter 3.

4.2 · Weight tying

At the end of the model you need to go the other way: from a C-dimensional vector back to a score for every vocabulary entry.

lm_head = nn.Linear(C, V, bias=False)     # weight shape (V, C)
logits = lm_head(x)                        # (B, T, C) → (B, T, V)

Notice lm_head.weight has shape (V, C) — the same shape as the embedding matrix. That is not a coincidence, and many models share the same tensor for both:

model.lm_head.weight = model.embed.weight     # weight tying
ApproachParamsUsed byRationale
TiedV·CGPT-2, Gemma, Qwen3-small, most <3B modelsSaves a lot of parameters when V·C is a big fraction of the model. Acts as a regulariser.
Untied2·V·CLlama-3-8B+, DeepSeek-V3, most large models"What a token means as input" and "what predicts it as output" are genuinely different functions. At large scale the extra parameters are cheap and help.

Rule of thumb: tie when the model is small (embeddings dominate the parameter count), untie when it's large (they're a rounding error and the extra capacity pays for itself).

4.3 · The residual stream — the model you should carry in your head

Here is the mental model. It comes from mechanistic interpretability work at Anthropic, and once you have it, transformers stop looking like a stack of boxes.

The residual stream

A transformer maintains, for each token position, one vector of size d_model that persists from the embedding all the way to the output. Call it the residual stream.

Every layer reads from the stream, computes something, and adds its result back. No layer ever replaces the stream. It is a running total — a shared blackboard that every layer writes to and every later layer can read.

x = embed(tokens)                 # (B, T, C)  ← the stream is born

for block in blocks:
    x = x + block.attn(block.ln1(x))     # attention writes into the stream
    x = x + block.mlp (block.ln2(x))     # MLP writes into the stream

logits = lm_head(final_norm(x))   # (B, T, V) ← the stream is read out

Look at the shape of x. It is (B, T, C) on every single line. A 70-billion parameter model with 80 layers has exactly one tensor shape running through its spine.

Why this model is so useful

  • It explains why gradients flow. The + means the gradient has a direct highway from the loss back to layer 1, bypassing every non-linearity. This is the whole reason ResNets and transformers can be 100+ layers deep. (§4.4)
  • It explains what layers "do". A layer isn't a transformation of everything; it's a specialist that reads a subspace and writes a subspace. Early layers write syntactic features; later layers write semantic ones.
  • It explains the logit lens. Because the stream lives in the same space throughout, you can apply the final unembedding to an intermediate layer's stream and get readable predictions. Doing so shows the model's guess sharpening layer by layer — an experiment you'll run in the notebook.
  • It explains "superposition". With d_model = 4096 but far more than 4096 concepts to represent, features must share dimensions at near-orthogonal angles. That's the central puzzle of interpretability research.
Bandwidth, precisely

The residual stream is a fixed-width communication channel. Every attention head and every MLP in the whole network competes for the same d_model dimensions. That is a real constraint, and it is one reason d_model scales with depth in practice: wider models can be deeper before the blackboard gets crowded.

4.4 · Why x + f(x) instead of f(x)

Consider the derivative of a residual block versus a plain block:

plain:   y = f(x)  →  ∂y∂x = f′(x)        residual:   y = x + f(x)  →  ∂y∂x = 1 + f′(x) the identity term is what keeps the gradient alive through 100 layers

Stack L plain layers and the gradient is a product of L Jacobians — if each has magnitude 0.9, after 80 layers you have 0.980 ≈ 0.0002 and the early layers learn nothing. With residuals, the product is of terms like (1 + f′), which stays near 1. That's it. That's the whole trick, and it's why He et al.'s ResNet paper (2015) is one of the most-cited papers in science.

Why does the residual connection help training deep networks?
∂(x + f(x))/∂x = 1 + f′(x), so gradients have a path that doesn't shrink multiplicatively
It reduces the number of parameters
It makes the forward pass faster
It prevents overfitting by adding noise
The identity term. Without it, backprop multiplies L Jacobians and the signal dies exponentially in depth. With it, there's an unobstructed highway from the loss to every layer. Note it costs a small amount of extra compute and memory, not less.

4.5 · What embeddings actually learn

The classic word2vec result — king − man + woman ≈ queen — holds, weakly, in transformer input embeddings too. But the more important modern finding is about the output side.

Because the unembedding maps the stream to vocabulary logits, directions in the residual stream correspond to "makes token X more likely". The final layernorm plus lm_head is a readout head, and you can apply it early:

# The "logit lens": decode an intermediate layer as if it were the last one.
with torch.no_grad():
    x = model.embed(ids)
    for i, blk in enumerate(model.blocks):
        x = blk(x)
        logits_i = model.lm_head(model.final_norm(x))     # (B, T, V)
        top = logits_i[0, -1].argmax().item()
        print(f"layer {i:2d}: {tokenizer.decode([top])!r}")

Run this and you typically see generic/frequent tokens early, snapping to the correct answer in the last third of the network. It is one of the most striking things you can observe in a language model with ten lines of code, and you'll do it in the notebook for Chapter 9.

4.6 · Exercises

4.1Embedding = one-hot matmulwarm-up

Prove the equivalence numerically. Build emb = nn.Embedding(10, 4), then show that emb(torch.tensor([3])) equals F.one_hot(torch.tensor([3]), 10).float() @ emb.weight. Then time both for V=50000. What's the speed ratio, and where does it come from?

Answer

They match exactly. The lookup is typically 100–1000× faster because the matmul does V×C multiply-adds (49,999 of every 50,000 by zero) plus materialises a (B, T, V) one-hot tensor, while the lookup does C memory reads. It's the same computation with completely different arithmetic intensity — a theme that returns in Chapter 12.

4.2Nearest neighbours in embedding spacecode

Load GPT-2's embedding matrix. Write nearest(word, k=10) that returns the k tokens whose embeddings have highest cosine similarity to a given token's embedding.

W = model.transformer.wte.weight            # (50257, 768)
Wn = W / W.norm(dim=-1, keepdim=True)       # normalise rows → cosine = dot

def nearest(token_str, k=10):
    i = tokenizer.encode(token_str)[0]
    sims = Wn @ Wn[i]                       # (50257,)
    top = sims.topk(k + 1).indices[1:]      # skip itself
    return [(tokenizer.decode([j]), sims[j].item()) for j in top]

Try " king", " Monday", " Paris", " 7". Note the leading spaces — Chapter 3 explains why they matter.

What to expect

" Monday" gives you the other weekdays, which is a clean win. " king" gives royalty-adjacent words but also a lot of noise. Input embeddings in a transformer are less semantically clean than word2vec vectors, because the model can defer meaning to later layers — the embedding only needs to be a useful starting point, not a finished representation.

4.3Break the residual streamessential

Take any small transformer implementation and change x = x + attn(ln(x)) to x = attn(ln(x)) in every block. Train both on the same tiny dataset for the same number of steps. Plot both loss curves.

What you'll see, and why

The residual-free model trains dramatically worse, and the gap widens with depth — at 2 layers it's marginal, at 8 layers it's severe, at 24 layers the non-residual version often fails to learn at all. Inspect block[0].attn.weight.grad.norm() in both: the non-residual version's first-layer gradients are orders of magnitude smaller. That measurement is the vanishing gradient problem, and it's much more convincing than reading about it.
