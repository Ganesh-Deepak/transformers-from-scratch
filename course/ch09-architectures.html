Why decoder-only won

Training efficiency. With a causal mask, a single forward pass over a length-T sequence produces T supervised predictions — every position predicts its successor. BERT-style masking only supervises the ~15% of positions that were masked. So a decoder extracts roughly 6× more learning signal per FLOP. Add that any task can be phrased as text continuation, and the case for a second architecture largely evaporated.

Encoder-only: BERT

# Training objective: mask 15% of tokens, predict them from BOTH sides.
"the cat [MASK] on the mat"  →  predict "sat"
# No causal mask — position 2 sees positions 0..5 freely.
# Cannot generate: there is no notion of "next".

Still the right tool for embeddings and reranking, where you want a rich bidirectional representation of a fixed text and don't need generation. Modern retrieval stacks still run BERT-family encoders.

Decoder-only: GPT and everything after it

# Training objective: predict token t+1 from tokens 0..t, at EVERY position at once.
input:  [the, cat, sat, on,  the]
target: [cat, sat, on,  the, mat]
# One forward pass = 5 predictions. The causal mask makes this valid.

Encoder–decoder: T5

# Encoder reads the source bidirectionally.
# Decoder generates causally, and CROSS-ATTENDS to the encoder output:
#     Q from decoder  (T_dec, d)
#     K, V from encoder output  (T_enc, d)
#     → output (T_dec, d)   — decoder length preserved, any encoder length

Still dominant where input and output are genuinely different modalities or languages — Whisper (audio→text) is the clearest current example.

9.2 · The full shape trace

This is the centrepiece of the chapter. A decoder-only model with B=2, T=6, V=32000, d_model=512, n_head=8, d_head=64, d_ff=1376, n_layer=6. Step through every tensor.

The off-by-one that everyone writes at least once 
logits  = model(ids)               # (B, T, V)
loss = F.cross_entropy(logits.reshape(-1, V), ids.reshape(-1))   # ← WRONG

This asks the model to predict the token it was just given — a task it solves perfectly by copying, and the loss goes to ~0 while the model learns nothing. You must shift:

loss = F.cross_entropy(
    logits[:, :-1, :].reshape(-1, V),      # predictions for positions 0..T-2
    ids[:, 1:].reshape(-1))                # targets are positions 1..T-1

Diagnostic: if your training loss drops below ln(1)≈0-ish absurdly fast, or below the entropy of your data, you have this bug. Some HF models shift internally when you pass labels=; check before doing it yourself, or you'll shift twice.

9.3 · The complete model, in one file

import torch, torch.nn as nn, torch.nn.functional as F
from dataclasses import dataclass

@dataclass
class Config:
    vocab_size: int = 32000
    d_model:    int = 512
    n_layer:    int = 6
    n_head:     int = 8
    d_ff:       int = 1376
    max_T:      int = 1024
    rope_base:  float = 10000.0

class GPT(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.cfg   = cfg
        self.embed = nn.Embedding(cfg.vocab_size, cfg.d_model)
        self.blocks = nn.ModuleList([Block(cfg) for _ in range(cfg.n_layer)])
        self.norm  = RMSNorm(cfg.d_model)
        self.head  = nn.Linear(cfg.d_model, cfg.vocab_size, bias=False)

        cos, sin = build_rope_cache(cfg.max_T, cfg.d_model // cfg.n_head, cfg.rope_base)
        self.register_buffer("cos", cos, persistent=False)
        self.register_buffer("sin", sin, persistent=False)

        self.apply(self._init)

    def _init(self, m):
        if isinstance(m, nn.Linear):
            nn.init.normal_(m.weight, std=0.02)
            if m.bias is not None: nn.init.zeros_(m.bias)
        elif isinstance(m, nn.Embedding):
            nn.init.normal_(m.weight, std=0.02)

    def forward(self, ids, targets=None):
        B, T = ids.shape                                    # (B, T)
        x = self.embed(ids)                                 # (B, T, C)
        cos, sin = self.cos[:T], self.sin[:T]

        for blk in self.blocks:
            x = blk(x, cos, sin)                            # (B, T, C)

        x = self.norm(x)                                    # (B, T, C)
        logits = self.head(x)                               # (B, T, V)

        loss = None
        if targets is not None:
            loss = F.cross_entropy(
                logits[:, :-1].reshape(-1, logits.size(-1)),
                targets[:, 1:].reshape(-1),
                ignore_index=-100)
        return logits, loss
Why std=0.02?

It's GPT-2's choice and it stuck. The principle is that activations should have roughly unit variance after each layer, which needs std ≈ 1/√d_model (0.044 at d_model=512). GPT-2 used a flat 0.02, plus an extra 1/√(2·n_layer) scaling on the residual output projections (W_o and MLP-down) to stop the residual stream's variance growing linearly with depth. That second detail is genuinely important and often omitted — see Exercise 9.3.

At which single point in the forward pass do different token positions exchange information?
The MLP
The attn @ v matmul (and the scores that produced it)
The final LM head
RMSNorm
Only in attention. The MLP, both norms, RoPE and the LM head all operate on each position independently — you could run them on a single token in isolation and get the same answer. Attention is the only cross-position operation in a transformer. That's worth holding onto: it means every claim about "how information flows through the model" is a claim about attention.
Which tensor in the trace is the largest, and why does that matter?
The residual stream, because it appears at every layer
The attention scores, always
It depends on T: logits (B·T·V) dominate at short T, attention scores (B·H·T²) dominate at long T
The QKV projection
It depends on sequence length. Here with T=6, V=32000: logits are 2×6×32000 = 384k elements vs scores at 2×8×36 = 576. But scores grow as T² while logits grow as T. Crossover for these numbers is around T = V/H = 4000. At T=32k the scores dominate overwhelmingly — which is exactly the regime FlashAttention was built for.
Your loss starts at 10.4 for a 32000-token vocabulary. Is that expected?
Yes — ln(32000) ≈ 10.37, which is the loss of a uniform random guess
No, it should start near 0
No, it should start near 1
Only if the model is broken
ln(V) is the expected initial loss. An untrained model outputs near-uniform logits, so cross-entropy = −ln(1/V) = ln(V) = ln(32000) ≈ 10.37. Always check this on step 0. If it starts much lower, your initialisation is too large or you have the label-shift bug. If much higher, your initialisation is broken. It's the cheapest sanity check in deep learning.

9.4 · Parameter counting, exactly

You should be able to derive a model's parameter count from its config. Here's the recipe:

def count_params(cfg, tied=False, swiglu=True):
    C, F_, L, V = cfg.d_model, cfg.d_ff, cfg.n_layer, cfg.vocab_size

    embed  = V * C
    attn   = 4 * C * C                       # W_q, W_k, W_v, W_o (MHA, no bias)
    mlp    = (3 if swiglu else 2) * C * F_
    norms  = 2 * C                           # two RMSNorms per block
    per_layer = attn + mlp + norms

    total = embed + L * per_layer + C        # + final norm
    if not tied:
        total += V * C                       # separate LM head
    return total

# GPT-2 small: C=768, F=3072, L=12, V=50257, GELU MLP, tied
count_params(Config(768, 3072, 12, 50257), tied=True, swiglu=False)
# 124,439,808  ≈ the famous "124M"  ✓
The shortcut worth memorising

For a dense transformer with d_ff = 4·d_model: N ≈ 12 · n_layer · d_model² (non-embedding). Attention is 4C², MLP is 8C². Check it: Llama-2-7B has L=32, C=4096 → 12 × 32 × 4096² ≈ 6.4B, and the true non-embedding count is ~6.5B. Close enough to do in your head.

9.2Verify causality empiricallyessential

Don't trust your mask — test it. Change token t and confirm that outputs at positions < t are bit-identical:

ids = torch.randint(0, 32000, (1, 10))
out1, _ = model(ids)

ids2 = ids.clone()
ids2[0, 7] = (ids2[0, 7] + 1) % 32000       # perturb position 7 only
out2, _ = model(ids2)

assert torch.allclose(out1[0, :7], out2[0, :7], atol=1e-6), "CAUSALITY VIOLATED"
assert not torch.allclose(out1[0, 7], out2[0, 7]),           "position 7 should change"
print("causal ✓")

Run this on every model you ever write. A subtly broken mask leaks the future, which makes training loss look fantastic and generation look insane — a failure mode that has cost people weeks.

9.3The residual-scaling initialisationcode

GPT-2 scales the residual-output projections at init by 1/√(2·n_layer). Implement it, then measure why:

for name, p in model.named_parameters():
    if name.endswith('proj.weight') or name.endswith('down.weight'):
        nn.init.normal_(p, std=0.02 / math.sqrt(2 * cfg.n_layer))

With and without it, run one forward pass and print x.std() after each block.

What you'll see

Without the scaling, the residual stream's standard deviation grows roughly as √n_layer — each block adds an independent contribution and variances sum. At 48 layers that's a ~7× growth, which pushes the final norm and the logits into a bad range and makes early training unstable. With the scaling, std stays roughly flat with depth. Two lines of code, and it's the difference between a training run that spikes and one that doesn't.
